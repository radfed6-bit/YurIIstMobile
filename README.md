# ЮрИИст — мобильное приложение (Android, полностью автономное)

React Native / Expo (TypeScript) приложение для личного использования.
**Отдельного сервера больше нет вообще** — всё, что раньше делал
`server.py` на Python, теперь работает прямо внутри приложения:

- **База законодательства** — та же `legal.db` (7545 статей, 28 кодексов
  и ППВС, полнотекстовый поиск FTS5) зашита в приложение как ассет и при
  первом запуске копируется на устройство. Поиск идёт локально, через
  `expo-sqlite`, без интернета.
- **Агентский цикл** (обращение к LLM, вызов инструментов, разбор
  ссылок на статьи) — порт `src/agent.py` на TypeScript
  (`src/lib/agent.ts`), выполняется прямо в приложении.
- **Инструменты агента** — `search_legal_db`/`get_article` читают
  локальную SQLite-базу; `web_search`/`web_fetch` обращаются в интернет
  напрямую с телефона (нужно подключение к сети только для этих двух
  инструментов и для самого вызова модели).

## Дизайн

Тот же современный минимализм, что и в предыдущей версии: нейтральная
палитра, пузыри сообщений, светлая/тёмная тема, приглушённое золото
только для подсветки ссылок на статьи в тексте ответа. Никакой
стилизации «под дело» (папка/печать/сшивка) из исходного сайта.

## Установка и запуск (Android)

Нужен Node.js 18+. Поскольку приложению нужен нативный модуль SQLite с
включённым FTS5, **Expo Go не подходит** — используем dev-client или
сразу полную сборку.

```bash
cd legalcli-mobile
npm install
npx expo install --fix     # подровняет версии под вашу версию Expo SDK
npx expo prebuild --platform android   # сгенерирует нативный проект android/
npx expo run:android       # соберёт и установит на подключённое устройство/эмулятор
```

Первый запуск на устройстве займёт чуть больше времени — приложение
копирует 62-мегабайтную базу из ассетов в свою файловую директорию
(см. экран загрузки «Подготовка базы законодательства…»). Дальше всё
работает уже без этого шага.

## Сборка .apk для установки на телефон

```bash
npm install -g eas-cli
eas login
eas build:configure
eas build --platform android --profile preview
```

`--profile preview` в стандартном `eas.json` обычно собирает `.apk`
(не `.aab`) — удобно устанавливать напрямую, без Google Play. Если в
вашем `eas.json` профиля `preview` нет, добавьте:

```json
{
  "build": {
    "preview": { "android": { "buildType": "apk" } }
  }
}
```

После сборки EAS даст ссылку на .apk — скачайте на телефон и
установите (разрешите установку из неизвестных источников).

Иконка/splash сейчас заглушки Expo — добавьте `assets/icon.png`
(1024×1024) и пропишите путь в `app.json`, если нужен свой фирменный
стиль.

## Структура

```
legalcli-mobile/
├── App.tsx
├── app.json                     # плагин expo-sqlite (enableFTS: true)
├── metro.config.js              # .db зарегистрирован как ассет
├── assets/legal.db              # база кодексов, 62 МБ, бандлится в .apk
├── src/
│   ├── theme.ts                  # дизайн-система
│   ├── types.ts
│   ├── lib/
│   │   ├── defaultConfig.ts      # встроенные ключ/модель/URL (из .env)
│   │   ├── database.ts           # копирование БД на устройство + open
│   │   ├── legalDb.ts            # search_legal_db / get_article (FTS5)
│   │   ├── tools.ts              # web_search / web_fetch + rate-limit
│   │   ├── htmlToText.ts         # HTML → текст для web_fetch
│   │   ├── agent.ts              # весь агентский цикл (порт agent.py)
│   │   └── storage.ts            # AsyncStorage: сессии, настройки
│   ├── components/                # UI (без изменений в этой итерации)
│   └── screens/ChatScreen.tsx    # экран целиком, без сети до LLM/web-инструментов
```

## Чего больше не нужно

- Python, `server.py`, `uvicorn`, деплой на VPS/Render — всё удалено из
  цепочки. Исходный `legalcli-website` проект можно оставить как
  референс/архив, для мобильного приложения он не требуется.
- Поля «адрес сервера» в настройках — убрано, приложение ни к какому
  внешнему бэкенду больше не обращается (кроме прямых вызовов модели и
  двух веб-инструментов).

## Известные ограничения

- APK получится заметно тяжелее (~70–90 МБ) из-за встроенной базы —
  ожидаемо для полностью офлайн-режима поиска по кодексам.
- Защита `web_fetch` от обращения к локальным/приватным адресам —
  урезанная версия серверной (нет полного DNS-резолва с проверкой всех
  IP, только проверка по строке хоста) — для личного однопользовательского
  приложения это приемлемый компромисс, но не такая же строгая защита,
  как была на сервере.
- Полная сборка (`npm install` / `eas build`) не прогонялась в этой
  сессии — в песочнице нет доступа к сети. Синтаксис всех файлов
  проверен через `tsc --noEmit`, ошибок нет; при первом реальном
  запуске возможны мелкие расхождения версий пакетов — их поправит
  `npx expo install --fix`.
